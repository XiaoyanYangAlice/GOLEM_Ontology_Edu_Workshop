# GOLEM工作坊：同人小说、人物与知识图谱

## 当粉丝改写人物，会发生什么？

[English](README.md)

粉丝如何重新诠释熟悉的人物？一个人物出现在新的故事中时，哪些特征得到保留，哪些关系或经历发生了变化？我们又如何把这些问题转化为数字人文研究？

本次入门工作坊从东亚粉丝文化与同人创作的实例出发，介绍 **GOLEM（Graphs and Ontologies for Literary Evolution Models）** 项目的研究问题，并探索如何用本体与知识图谱表示作品、虚构人物、人物特征、关系和叙事事件。

课程最后将使用Google Colab进行带领式练习：运行预先准备的SPARQL查询、阅读结果，并尝试修改一个简单参数。**不要求具备Python、RDF或SPARQL基础。**

本课程改编自DHBenelux 2026的GOLEM工作坊，并结合早期东亚文化研究报告中的案例。历史统计和截图保留其原有语境，不代表平台当前的实时情况。

## 学习目标

完成课程后，你将能够：

- 举例说明同人小说数据可以支持哪些文化与文学研究问题。
- 区分平台元数据与人物、故事内容的信息。
- 理解具体作品中的人物实例，与连接不同作品人物实例的Character-Stoff概念之间的区别。
- 识别RDF三元组和简单SPARQL查询的基本结构。
- 运行准备好的查询，并解释结果能够支持什么判断、有哪些范围限制。

## 课前准备

如希望同步操作，请携带可联网的笔记本电脑，也可以与同学结对跟做。

1. 确认能够打开[Google Colab](https://colab.research.google.com/)。在Colab中运行和保存notebook通常需要Google账号。
2. 从上方材料区下载教学notebook。
3. 在Colab选择 **File → Upload notebook**，上传下载的`.ipynb`文件。
4. 将在线本体文档放在方便查阅的位置。

无需提前安装本地Python，也无需提前完成练习。课堂会一起运行初始化单元。在线服务和教学数据可能更新，请以教师提供的课堂版notebook及连接设置为准。

## 30分钟实践内容

主讲人将共享notebook屏幕，带领大家完成以下操作：

| 时间 | 内容 |
|---|---|
| 0–5分钟 | 打开notebook，运行初始化单元 |
| 5–11分钟 | **Query 1.1：作品标题与作者**。运行查询，将`LIMIT 10`改为`LIMIT 5`并观察变化 |
| 11–17分钟 | **Query 1.2：作品指标**。查看hits、kudos等指标，阅读结果表 |
| 17–25分钟 | **Query 2.1：人物与作品**。查看哪些人物出现在哪些同人作品中 |
| 25–28分钟 | 处理操作问题与答疑；进度顺利时，加做 **Query 2.2：受害者角色** |
| 28–30分钟 | 总结查询结果，讨论可以继续研究的问题 |

练习使用与希腊神话相关的教学数据。查询结果描述的是当前查询的数据集，不能直接推广到整个AO3。同样，人物的叙事角色、具体叙事事件与平台标签也是不同层面的信息。

## 阅读清单

### 课前：建立基本印象

**不要求提前读完研究论文。** 如时间允许，可用约 **10–15分钟** 浏览以下内容：

### 推荐阅读

- **[The GOLEM Ontology for Narrative and Fiction](https://www.mdpi.com/2076-0787/14/10/193)**，发表于 *Humanities*，2025，14(10)，193。适合了解GOLEM的建模思路，以及文学研究问题如何影响本体设计。
- **[人物本体研究稿件](https://www.semantic-web-journal.net/system/files/swj4094.pdf)**。适合进一步了解虚构人物的建模问题。可作为本课程的延伸阅读。

## 课后探索

完整notebook还包括发表年份、互动指标筛选、标签、叙事角色、人物关系、人物特征，以及原作与同人作品之间的比较。

探索时可以始终带着一个问题：**你希望比较同一人物在不同改写中的什么变化？为了回答它，还需要哪些数据或标注？**
